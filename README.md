# はなせる

**使ってみる: [fatcorn753.github.io/hanaseru](https://fatcorn753.github.io/hanaseru/)**(スマホではホーム画面に追加するとアプリとして使えます)

会話への怖さを、**小さな行動実験**で少しずつほどいていく練習アプリ(PWA)です。

緊張をゼロにすることはめざしません。緊張していても会話を避けずに済み、終わったあと引きずらない状態をめざします。

> このアプリは練習用の道具で、病気の診断や治療をするものではありません。つらさが強いときは、医療機関や [相談窓口](https://www.mhlw.go.jp/mamorouyokokoro/) を頼ってください。

## しくみ

社交不安への認知行動療法で効果が大きいのは、現実の会話を「行動実験」として試し、**予想した最悪が起きなかったことを自分で確かめる**ことです。アプリ内での練習は、その実験を支える脇役です。

| 機能 | 内容 | 主な根拠 |
| --- | --- | --- |
| 実験ループ | 予想(最悪のこと・確信度・緊張)→ お守り行動を 1 つ外す → 現実で試す → 結果と比べる | Clark et al. 2006; Craske et al. 2014 |
| 課題のはしご | 雑談・初対面/発表・人前で話す/職場・バイトのやりとり/頼む・断る の 4 場面、各 6 段階で計 76 課題。場面ごとに、予想が外れる体験が続いたら次の段を提案。睡眠不足の日は 1 段軽く | Mayo-Wilson et al. 2014; Ben Simon & Walker 2018 |
| 外に注意を向けるお題 | 「相手の話の名詞を 3 つ覚える」など | Wells & Papageorgiou 1998 |
| 会話後の反省会チェック | 実験の 15 分〜48 時間後に、事実と解釈の仕分けか、自分への声かけへ誘導 | Brozovich & Heimberg 2008; Shikatani et al. 2014 |
| スキル道場 | 深掘り質問・言い換え・締め方・話題の入り方・自己開示・あいづち・沈黙・質問と報告・頼み方・断り方・人前での注意の向け先 | Huang et al. 2017; Mastroianni et al. 2021; Aron et al. 1997; Brooks et al. 2015; Flynn & Lake 2008; Givi & Kirk 2024 ほか |
| 台本会話 | 授業前・バイトの休憩・サークル・美容院・職場での質問と報告・ミスを伝える・誘いを断る・頼む、の 8 本を分かれ道つきで練習。声に出して答えてから近い返しを選び、話し始めるまでの時間を測る | Mayo-Wilson et al. 2014; Templeton et al. 2022 |
| 人前で話すリハーサル | 時間を決めて声に出して話し、話した時間と 2 秒以上の間を端末内で測る。話す前と後に「緊張は外からどのくらい見えるか」を見積もり、ビデオ振り返りにつなげる | Savitsky & Gilovich 2003; Ebrahimi et al. 2019 |
| ビデオ振り返り | 見る前に見え方を予想し、他人として見て比べる。録画は保存しない | Harvey et al. 2000 |
| 整える | ため息呼吸・ゆっくり呼吸・ドキドキの読み替え・心配の書き出し・筋弛緩・セルフコンパッション | Balban et al. 2023; Brooks 2014; Ramirez & Beilock 2011; Neff 2003 |

### 続けやすさのための設計判断

- 一般公開のメンタルヘルスアプリの 30 日継続率は中央値で約 3%(Baumel et al. 2019)。
- 0 に戻る連続記録・ランキング・ポイントは入れていません。社交不安のある人には比較や失敗への恐れを強めるおそれがあるためです。
- 記録の主役は不安の強さではなく「予想と結果のずれ」です。症状ばかりを見張ると、自分への注目が強まるためです。

## データとプライバシー

- 記録はすべて端末のブラウザ(IndexedDB)の中にだけ保存されます。サーバーはありません。
- 設定画面から JSON で書き出し・読み込みができます。
- ビデオは再生後に破棄し、保存も送信もしません。
- 台本会話とリハーサルのマイクは、音量を端末の中で測るだけで、録音も送信もしません。
- 台本会話の「話した言葉を文字にする」は既定でオフです。オンにすると、ブラウザによっては音声が提供元(Google や Apple)のサーバーに送られます。デスクトップ版 Chrome などで端末内の文字起こしが使えるときは、そちらを使います。文字にした内容は保存しません。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm test         # Vitest
npm run build    # 型チェック + 本番ビルド(dist/)
```

GitHub Pages のサブパスで配信するときは `BASE_PATH=/hanaseru/ npm run build`。

### 感想・不具合と実機確認

- 感想と不具合は GitHub Issues のテンプレート(`.github/ISSUE_TEMPLATE/`)で受け付けます。アプリの設定画面と記録画面からリンクしています。
- 実機での確認手順は [docs/device-test-checklist.md](docs/device-test-checklist.md) にあります。

### 内容を増やす

課題は `src/content/missions.ts`、ドリルは `src/content/drills.ts`、台本会話は `src/content/scripts.ts` にあります。`npm test` が ID の重複や参照切れ、台本の行き止まりやたどり着けない場面を検査します。追加するときは根拠となる文献を添えてください。
